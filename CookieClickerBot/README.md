# Cookie Clicker Bot

Cookie Clicker をブラウザー上で自動操作する、Windows 対応の Python 製ボットです。クリック、施設・アップグレード購入、農業、株式市場、神殿、魔法書、ドラゴン、サンタ、季節、転生などを管理画面から制御できます。

ボットの操作結果やエラーは `logs/` に記録され、ゲームのセーブコードは `saves/` にバックアップできます。ゲーム本体のファイルを書き換えるのではなく、ブラウザー内の Cookie Clicker API を呼び出して動作します。

> **README の対象について**  
> このファイルは、2026-10-31 に確認した GitHub `main` ブランチの `CookieClickerBot/` を基準に内容を整理したものです。README の更新だけでは、プログラム本体のバージョンや機能は変わりません。現在の GitHub ソースでは Python と JavaScript のバージョン表示はいずれも `1.0.0` です。別途作成された累積パッチ v1.6.2 を適用・確認するまでは、プログラムが v1.6.2 になったとは扱わないでください。

## 主な機能

| 分類 | 内容 |
|---|---|
| クリック | 大きなクッキーを自動クリックします。通常のクリック経路では、ゲーム側のオートクリッカー検出を考慮して実効最大 14.5 回/秒に制限します。 |
| ゴールデンクッキー | 通常のゴールデンクッキーを自動回収します。レッド（怒り）クッキーは個体ごとに一度だけ確率判定します。 |
| シワシワ | 残す匹数、キラキラ個体の優先破裂、吸収量による破裂条件を設定できます。 |
| アップグレード | 購入戦略、購入除外リスト、ホワイトリスト、季節トグルや研究系の購入方針を設定できます。 |
| 施設 | 価格と CpS 増加量から回収効率を測定する方式、または最安優先方式で購入します。 |
| 砂糖ランプ | 成熟したランプの収穫と建物レベルアップを自動化します。 |
| 農業（庭） | 植栽、収穫、土壌選択、雑草管理、種の変異・解放計画、ランプ農園を支援します。 |
| 株式市場 | 基準値、価格の勢い、損切り・利確条件などに基づく売買を行います。 |
| 神殿（パンテオン） | 設定したロードアウトに従って神を配置します。配置にはゲームの礼拝スワップ制限を適用します。 |
| 魔法書（グリモア） | 設定した呪文を優先順に詠唱します。既定では暴走率が高い呪文を避けます。 |
| ドラゴン | 解放状態を確認してから育成し、習得済みのオーラを設定します。第2オーラ枠はゲーム側の解放条件を確認します。 |
| サンタ | 「A festive hat」の購入状態を確認してからレベルアップします。 |
| 季節 | 指定した季節への切り替えを支援します。既定では自動切り替え OFF です。 |
| 転生 | プレステージ獲得条件を監視し、設定に応じて転生します。転生前バックアップ確認と天界アップグレード購入処理があります。 |
| 管理画面 | 状態、設定、ログ、セーブ、ミニゲーム情報をローカル Web UI で確認できます。 |

### 実績について

現在確認した GitHub ソースでは、ゲーム本体が保持する実績数（解除済み数）の状態取得はありますが、実績を優先的に自動解除する独立したアシストモジュールは確認できませんでした。実績フラグを直接書き換える、または `Game.Win()` を使って強制解除する機能は、このソースの実装機能として案内しません。

## インストール

1. ZIP を任意の作業フォルダーに展開します。
2. `install.bat` を実行します。
3. Python の確認後、プロジェクト内に `.venv` を作成し、`requirements.txt` の依存ライブラリを導入します。
4. Playwright の Chromium をダウンロードします。Chromium のダウンロードに失敗しても、Chrome / Edge が利用できる環境では `config.json` の `browser.channel` を `chrome` または `msedge` に変更して利用できる場合があります。
5. セットアップの最後に `run.py --doctor` による環境診断が実行されます。

診断だけをやり直す場合は `doctor.bat` を使用します。

## 起動・停止

### 起動

```bat
start_bot.bat
```

既定の管理画面 URL は次のとおりです。

```text
http://127.0.0.1:8765/
```

`start_bot.bat` は引数を `run.py` に渡します。例：

```bat
start_bot.bat --port 8888
start_bot.bat --headless
start_bot.bat --channel msedge
start_bot.bat --no-open
```

### 停止

- 起動したコンソールで `Ctrl+C` を押す。
- または管理画面の `[停止]` を使用する。

終了時には、設定で `save.backupOnExit` が有効なら終了時セーブの取得を試みます。取得できない場合は、利用可能な内部チェックポイントまたは過去の正常バックアップから `exit-fallback` を作成しようとします。フォールバックは終了時点そのものの最新状態とは限らず、チェックポイント以降の操作が失われる可能性があります。ログで参照元と経過時間を確認してください。

管理画面は既定で `127.0.0.1:8765` にバインドされます。主な画面は次のとおりです。

| 画面 | 内容 |

| ダッシュボード | クッキー、CpS、プレステージ、バフ、施設、シマー、モジュール状態、直近イベントなど。 |
| モジュール設定 | `config.json` の各モジュール設定を表示・編集します。設定内容は保存され、エンジンへ反映されます。 |
| 施設・ストア | 施設やアップグレードの一覧・購入操作。 |
| 農業 | 庭の状態、植栽、収穫、種、土壌、自動計画。 |
| 取引所 | 株価、保有量、取引履歴、売買操作。 |
| 神殿・魔法 | パンテオンのスロット、神の情報、呪文、ドラゴン、サンタ、季節の状態。 |
| 転生・天界 | 転生条件、天界アップグレード、恒久アップグレード枠。 |
| ログ | 行動ログの検索、モジュール絞り込み、ログファイルの取得。 |
| セーブ | バックアップ一覧、復元、ダウンロード、削除、セーブコードの入出力。 |

## 主な設定

設定ファイルはプロジェクト直下の `config.json` です。初回起動時に `ccbot/config.py` の既定値から作成されます。既存の `config.json` がある場合、コード側の既定値を変更しても既存値が自動的にすべて置き換わるわけではありません。

よく使う設定：

| キー | 既定値 | 内容 |
|---|---:|---|
| `master` | `true` | すべての自動処理の全体スイッチ。 |
| `clicker.cps` | `12` | クリック速度の目標値。実効上限は 14.5 回/秒です。 |
| `golden.popGolden` | `true` | 通常のゴールデンクッキーを自動回収します。 |
| `golden.popWrath` | `true` | レッドクッキーの確率判定を有効にします。`false` なら自動回収しません。 |
| `golden.wrathPopChancePercent` | `5` | レッドクッキー1個につき初回検出時に一度だけ行う回収確率（%）。 |
| `wrinkler.keep` | `10` | 残すシワシワの匹数。 |
| `building.strategy` | `payback` | 施設購入方針。`payback` は回収効率、`cheapest` は最安優先です。 |
| `garden.mode` | `auto` | 庭の運用モード。詳細は管理画面の説明を参照してください。 |
| `market.buyBelowRatio` | `0.80` | 基準値に対する購入価格の上限倍率。 |
| `market.sellAboveRatio` | `1.35` | 基準値に対する売却価格の下限倍率。 |
| `pantheon.autoSlot` | `true` | パンテオンの自動配置。 |
| `pantheon.loadout` | `creation, scorn, order` | 現在の GitHub ソースにある既定ロードアウト。スクルーイヤ禁止パッチ適用前の値です。 |
| `dragon.autoTrain` | `true` | ドラゴンの自動育成。未解放時は処理を行いません。 |
| `santa.autoUpgrade` | `true` | サンタの自動レベルアップ。未解放時は処理を行いません。 |
| `ascend.percent` | `50` | 現在のプレステージに対する転生獲得条件の増加率。 |
| `ascend.backupFirst` | `true` | 自動転生前にバックアップ確認を要求します。 |
| `save.backupEverySec` | `900` | 通常の定期バックアップ間隔（秒）。 |
| `save.backupOnAscend` | `true` | 転生前バックアップを有効にします。 |
| `save.backupOnExit` | `true` | 終了時バックアップを有効にします。 |
| `save.keepBackups` | `60` | 通常バックアップの保持数。 |

設定の全項目・型・選択可能な値は、実際の `ccbot/config.py` と管理画面の表示を優先してください。

## ゴールデンクッキーとレッドクッキー

現在確認した `20_basic.js` の自動処理は、次の動作です。

- 通常のゴールデンクッキー：`golden.popGolden` が ON なら自動回収します。
- レッド（怒り）クッキー：`golden.popWrath` が ON の場合、`wrathPopChancePercent` によって回収可否を判定します。
- 判定結果はシマー個体ごとにキャッシュされるため、画面上に表示されている間にスケジューラーが何度実行されても抽選をやり直しません。
- 既定値 5% は「ちょうど20個ごとに必ず1個」ではなく、各個体で独立した5%の確率です。長期的な平均が約20個に1個という意味です。
- 通常のランダムなレッドクッキーは、クリック前に良い効果か悪い効果かを確実に判定できません。5%設定では良い効果も悪い効果も同じ確率で回収対象になります。

**手動操作の注意：** 現在の `90_api.js` では、管理画面のクイック操作「ゴールデン回収」が `popShimmers` の全回収指定を使用します。この手動操作は自動処理の5%抽選を経由しないため、レッドクッキーも回収する場合があります。自動処理の5%方針を維持したいときは、この一括手動回収を押さないでください。

## パンテオンとスクルーイヤ

### 現在の GitHub ソース

確認した `main` ブランチの `ccbot/config.py` と `00_core.js` では、既定ロードアウトに `scorn`（スクルーイヤ）が含まれています。また、同ブランチの `60_temple_grimoire.js` の `Bot.slotGod()` には、スクルーイヤの配置を拒否する処理がまだありません。

したがって、**GitHub上の元ソースだけではスクルーイヤ配置は禁止されていません。** README の差し替えだけでも配置は禁止されません。

### 累積パッチ v1.6.2 を適用した場合

別途作成された v1.6.2 パッチの設計では、次の制御を追加します。

- BOTが管理する自動配置・手動APIの両方で、スクルーイヤの配置を拒否する。
- 既存のロードアウトや `config.json` に残る `scorn` / `Skruuia` / 対応する別名を除外する。
- 管理画面の神選択肢からスクルーイヤを除外する。
- すでにスロットにいる場合は、スロット解除（ゲーム上無料の操作）を試みる。
- 空いたスロットには別の神を勝手に補充しない。

この制御は CookieClickerBot が管理する配置経路に対するものです。ゲーム本体のパンテオン画面でユーザーが直接行う操作までは無効化しません。パッチを適用しただけで実ゲーム上の解除が成功したと断定せず、適用後のログとゲーム画面で確認してください。

## ドラゴン・サンタ

確認したソースには、次の解放チェックがあります。

- ドラゴンは「A crumbly egg」の購入状態を確認し、未解放なら自動育成・オーラ設定を行いません。
- 第2オーラ枠は `dragonLevels` の最大レベル到達を確認します。
- 手動APIでもドラゴン未解放、第2枠未解放、同じオーラの二重設定を拒否します。
- サンタは「A festive hat」の購入状態を確認してから `UpgradeSanta()` を呼び出します。

管理画面の表示と操作ボタンにも解放状態が反映されます。ゲーム内の解放条件やアップデートで API が変わる場合は、実ゲームで再確認してください。

## 転生と天界アップグレード

確認した `70_ascend.js` と Python エンジンには、次の安全処理があります。

1. 初回転生のみ、既定では予測プレステージが 365 未満なら自動転生を保留します。すでに転生履歴がある場合、この初回専用条件では次回転生を止めません。
2. 自動転生を実行する前に `pendingAscend` を作り、Python 側でセーブコードを書き出します。
3. バックアップが存在しない、空、読み出し不可、または承認応答が確認できない場合は、バックアップ承認を送らず転生を保留します。タイムアウトしただけで転生を強行する設計ではありません。
4. 転生画面では、購入可能な天界アップグレードが残っている間、次の処理パスで購入を続けます。
5. 購入一覧を取得できない場合や、最終確認で購入可能項目が残っている場合は現世復帰を保留します。
6. 恒久アップグレード枠の割り当ても、設定と所持状況を確認して実行します。

**注意：** 管理画面の「今すぐ転生」は明示的な手動操作です。転生は進行をリセットする破壊的な操作なので、押す前に必ずゲーム内の状態とバックアップを確認してください。自動転生の条件判定と手動転生ボタンは同じ操作ではありません。

## セーブとバックアップ

### 保存場所

- `browser_profile/`：Chromium のユーザープロファイル。Cookie Clicker の localStorage などゲーム進行に関係するデータが含まれます。
- `saves/`：エクスポートしたセーブコードのバックアップ。
- `saves/.ccbot/last_live_checkpoint.txt`：エンジンが定期的に更新する内部チェックポイント。通常のバックアップ一覧とは別に保持されます。

**`browser_profile/` を削除するとゲーム進行が失われる可能性があります。** アンインストールやフォルダー整理の前に、必ず `saves/` と `browser_profile/` を別の場所へコピーしてください。

### 主なバックアップタグ

| タグ | タイミング |
|---|---|
| `periodic` | 定期バックアップ。既定は15分間隔。 |
| `pre-ascend` | 自動転生前。 |
| `exit` | ボット終了時にゲームから取得したセーブ。取得処理は再試行します。 |
| `exit-fallback` | 終了時にライブ取得できなかった場合、内部チェックポイントまたは過去の正常バックアップを複製したもの。 |
| `before-restore` | セーブ復元の直前。 |
| `manual` | 管理画面からの手動バックアップ。 |

`exit-fallback` は必ずしも終了時点の最新セーブではありません。元になったチェックポイントやバックアップの時刻以降の進行は含まれないことがあります。ファイル名だけで新旧を判断せず、`logs/` のバックアップログも確認してください。

### 復元

管理画面の `[セーブ]` タブで対象バックアップを選び、復元します。復元前には現在の状態が `before-restore` として保存される設計ですが、復元操作自体も進行を置き換えるため、対象ファイルと日時を慎重に確認してください。

## ログ

ログは `logs/` に保存されます。主なファイル・フォルダー：

```text
logs/
├── ccbot.log          システムログ
├── error.log          警告・エラー
├── actions/           行動ログ（テキスト / JSONL）
└── stats/             定期的な状態スナップショット
```

ログには、時刻、モジュール、操作、購入・収穫・配置などの内容、結果、エラー情報が記録されます。問題が起きた場合は、まず `logs/ccbot.log` と `logs/error.log` を確認してください。

ログにはゲーム内の進行状況やユーザー環境のパスなどが含まれる場合があります。共有するときは、個人情報・認証情報が含まれていないか確認してください。

## アンインストール

```bat
uninstall.bat
```

対話式で `.venv` の削除、Playwright ブラウザーの削除、設定・ログ・セーブ・ブラウザープロファイルの削除を選べます。

- 再インストールするだけなら、設定・ログ・セーブ・`browser_profile/` を残してください。
- 完全削除を選ぶとゲーム進行データも消える可能性があります。
- 実行前に BOT を停止し、必要なバックアップを別フォルダーへコピーしてください。

## トラブルシューティング

| 症状 | 確認・対処 |
|---|---|
| `install.bat` で Python が見つからない | Python をインストールし、`Add python.exe to PATH` を有効にしてから再実行します。 |
| Chromium のダウンロードに失敗する | ネットワークを確認します。Chrome / Edge を使用する場合は `browser.channel` を変更します。 |
| `Just a moment...` などの人間認証画面 | ブラウザーを表示モードで開き、画面の指示に従って手動で認証します。ボットが認証を自動解除する設計ではありません。 |
| 管理画面が開かない | ポート競合の可能性があります。`start_bot.bat --port 8888` など別ポートで起動します。 |
| `game not ready` が続く | ゲーム読み込み、ネットワーク、ブラウザー画面、`logs/ccbot.log` を確認します。 |
| 庭・市場・神殿・魔法が利用できない | 対応する建物の購入・レベル・ミニゲーム解放状態を確認します。 |
| 終了時バックアップが `exit-fallback` になった | 終了時のライブセーブ取得ができず、内部チェックポイント等を退避した状態です。ログで参照元と経過時間を確認します。 |
| 転生が保留される | `pre-ascend` バックアップの作成・読み出し・承認ログを確認します。バックアップを確認できないときは転生を強行しないでください。 |
| パッチの Preflight が失敗する | その場で停止し、エラー全文を保存してください。古いアンカーを手動で書き換えたり、Preflight を無効化して続行したりしないでください。 |

## テスト

プロジェクトには、用途の異なる複数のテストがあります。実行環境に応じて必要な依存ライブラリを用意してください。

```bat
:: JavaScript エンジン（モックゲーム）
node tests\run_engine_test.js

:: Python 設定・ログ・セーブ・管理画面 API
.venv\Scripts\python.exe tests\test_python.py

:: 管理画面 UI スモークテスト（Playwright が必要）
.venv\Scripts\python.exe tests\test_ui.py

:: 実ゲームを使う基本 E2E テスト（ブラウザー / ネットワークが必要）
.venv\Scripts\python.exe tests\test_live.py

:: ミニゲーム・転生を含む実ゲームの発展テスト
.venv\Scripts\python.exe tests\test_advanced.py

:: 管理画面スクリーンショットの生成
.venv\Scripts\python.exe tests\gen_screenshots.py
```

### テスト時の注意

- `run_engine_test.js` はモックゲームを使用します。成功しても、公式ゲーム上で同じ動作が確認されたことにはなりません。
- `test_ui.py` は管理画面の描画確認用です。実ゲームの全機能を検証するテストではありません。
- `test_live.py` は実際のゲームサイトを読み込み、ボットを動かします。テスト用ブラウザープロファイルで実行してください。
- `test_advanced.py` はゲーム状態をテスト用にセットアップする処理を含みます。普段使用している `browser_profile/` やメインのセーブデータで実行しないでください。
- テストの合格数はソースの変更で変わります。古いレポートに記載された件数を、現在のテスト結果として扱わないでください。
- テストを実行していない場合は、成功したと報告しないでください。モック、隔離コピー、Windows 実機、公式ゲームでの確認を区別してください。
